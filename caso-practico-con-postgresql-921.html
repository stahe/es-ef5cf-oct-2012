    6. Caso práctico con PostgreSQL 9.2.1

    6.1. Instalación de las herramientas

    Las herramientas que hay que instalar son las siguientes:

    • el SGBD: [http://www.enterprisedb.com/products-services-training/pgdownload#windows];
    • una herramienta de administración: EMS SQL Manager for PostgreSQL Freeware [http://www.sqlmanager.net/fr/products/postgresql/manager/download].

    En los siguientes ejemplos, el usuario postgres tiene la contraseña postgres.

    Iniciemos PostgreSQL y, a continuación, la herramienta [SQL Manager Lite for PostgreSQL], que utilizaremos para administrar el DBMS.

    • En [1], iniciamos el SGBD PostgreSQL desde Servicios de Windows;
    • En [2], el servicio se ha iniciado;

    Ahora iniciamos la herramienta [SQL Manager Lite for MySQL], que utilizaremos para administrar el SGBD [3].

    • En [4], creamos una nueva base de datos;
    • En [5], especificamos el nombre de la base de datos;
    • En [5], iniciamos sesión como postgres / postgres;
    • En [6], ofrecemos cierta información;
    • En [7], validamos la instrucción SQL que se va a ejecutar;
    • En [8], se ha creado la base de datos. Ahora debe registrarse en [EMS Manager]. La información es correcta. Haga clic en [Aceptar];
    • En [9], conéctese a ella;
    • En [10], [EMS Manager] muestra la base de datos, que actualmente está vacía. Tenga en cuenta que las tablas pertenecerán a un esquema llamado public [11].

    Ahora conectaremos un proyecto de VS 2012 a esta base de datos.

    Comenzamos duplicando la carpeta del proyecto [RdvMedecins-SqlServer-01] en [RdvMedecins-PostgreSQL-01] [1]:

    • en [3], el proyecto se ha eliminado;

    • en [6], lo renombramos como [RdvMedecins-PostgreSQL-01];
    • En [7], añadimos otro proyecto a la solución. Este se toma de la carpeta [RdvMedecins-SqlServer-01] del proyecto que eliminamos anteriormente de la solución;
    • en [8], el proyecto [RdvMedecins-SqlServer-01] se ha vuelto a añadir a la solución.

    La línea 1 indica que el conector ADO.NET de PostgreSQL no puede eliminar la base de datos existente. Al igual que con Oracle. Por lo tanto, debemos crear la base de datos [RDVMEDECINS-EF] manualmente utilizando la herramienta [EMS Manager for PostgreSQL]. No describiremos todos los pasos, sino solo los más importantes.

    La base de datos PostgreSQL tendrá la siguiente estructura:

    Las tablas

    • En [1], ID es una clave primaria de tipo serial. Este tipo de PostgreSQL es un entero generado automáticamente por el SGBD.

    Las distintas tablas tienen las claves primarias y externas que estas mismas tablas tenían en los ejemplos anteriores. Las claves externas tienen el atributo ON DELETE CASCADE.

    Secuencias

    Al igual que en Oracle, aquí hemos creado secuencias. Se trata de generadores de números consecutivos. Hay cinco [1].

    • En [2], vemos las propiedades de la secuencia [CLIENTS_ID_SEQ]. Genera números consecutivos en incrementos de 1, empezando por 1 hasta un valor muy grande.

    Todas las secuencias se basan en el mismo modelo.

    • [CLIENTS_ID_seq] se utilizará para generar la clave principal de la tabla [CLIENTS];
    • [MEDECINS_ID_seq] se utilizará para generar la clave principal de la tabla [MEDECINS];
    • [SLOTS_ID_seq] se utilizará para generar la clave principal de la tabla [SLOTS];
    • [RVS_ID_seq] se utilizará para generar la clave principal de la tabla [RVS];
    • [sequence_versions] se utilizará para generar los valores de las columnas [VERSIONING] en todas las tablas.

    Desencadenadores

    Un disparador es un procedimiento ejecutado por el SGBD antes o después de un evento (Insert, Update, Delete) en una tabla. Tenemos 4 de ellos [1]:

    Veamos el código DDL del disparador [CLIENTS_tr], que rellena la columna [VERSIONING] de la tabla [CLIENTS]:

    1
2
3
4
    CREATE TRIGGER "CLIENTS_tr"
  BEFORE INSERT OR UPDATE 
  ON public."CLIENTS" FOR EACH ROW 
EXECUTE PROCEDURE public.trigger_versions();
    • líneas 1-3: antes de cada operación INSERT o UPDATE en la tabla [CLIENTS];
    • Línea 4: Se ejecuta el procedimiento [public.trigger_versions()].

    El procedimiento [public.trigger_versions()] es el siguiente:

    1
2
3
4
    BEGIN
NEW."VERSIONING":=nextval('sequence_versions');
return NEW;
END
    • Línea 2: NEW representa la fila que está a punto de insertarse o modificarse. NEW. «VERSIONING» es la columna [VERSIONING] de esa fila. Se le asigna el siguiente valor del generador de números «sequence_versions». Por lo tanto, la columna [«VERSIONING»] cambia con cada INSERT o UPDATE que se realiza en la tabla [CLIENTS].

    Los desencadenadores [MEDECINS_tr, CRENEAUX_tr, RVS_tr] funcionan de la misma manera. Las cuatro columnas ["VERSIONING"] obtienen sus valores de la misma secuencia.

    El script para generar las tablas en la base de datos PostgreSQL [RDVMEDECINS-EF] se ha colocado en la carpeta [RdvMedecins / databases / postgreSQL]. El lector puede cargarlo y ejecutarlo para crear las tablas.

    6.3. Arquitectura multicapa basada en EF 5

    Volvemos al caso práctico descrito en el párrafo 2.

    Comenzaremos por crear la capa de acceso a datos [DAO]. Para ello, duplicamos el proyecto de consola de VS 2012 [RdvMedecins-SqlServer-02] en [RdvMedecins-PostgreSQL-02] [1]:

    • En [2], elimine el proyecto [RdvMedecins-SqlServer-02];
    • En [3], añada un proyecto existente a la solución. Tómelo de la carpeta [RdvMedecins-PostgreSQL-02] que acaba de crear;
    • En [4], el nuevo proyecto tiene el mismo nombre que el que se ha eliminado. Vamos a cambiarle el nombre;
    • En [5], hemos cambiado el nombre del proyecto;
    • En [6], modificamos algunas de sus propiedades, como el nombre del ensamblado;
    • en [7], se elimina la carpeta [Models] y se sustituye por la carpeta [Models] del proyecto [RdvMedecins-PostgreSQL-01]. Esto se debe a que ambos proyectos comparten los mismos modelos.
    • en [8], las referencias actuales del proyecto;
    • en [9], se ha añadido el conector PostgreSQL ADO.NET mediante la herramienta NuGet.

    En el archivo [App.config], sustituya la información de la base de datos de SQL Server por la de la base de datos PostgreSQL. Esta información se encuentra en el archivo [App.config] del proyecto [RdvMedecins-PostgreSQL-01]:

    <add name="monContexte" connectionString="Server=127.0.0.1;Port=5432;Database=rdvmedecins-ef;User Id=postgres;Password=postgres;" providerName="Npgsql" />
  </connectionStrings>
  <!-- the factory provider -->
  <system.data>
    <DbProviderFactories>
      <add name="Npgsql Data Provider" invariant="Npgsql" support="FF" description=".Net Framework Data Provider for Postgresql Server" type="Npgsql.NpgsqlFactory, Npgsql, Version=2.0.11.0, Culture=neutral, PublicKeyToken=5d8b90d52f46fda7" />
    </DbProviderFactories>
